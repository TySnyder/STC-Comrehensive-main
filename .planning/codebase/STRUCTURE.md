## Directory Purposes

**`src/`:**
- Purpose: All application source code (TypeScript/React)
- Contains: Components, types, data, entry points, styles
- Key files: App.tsx (root), main.tsx (entry), types.ts (domain model)

**`src/components/`:**
- Purpose: React UI components
- Contains: View components (one per tab), layout components, modal components
- Naming: PascalCase with .tsx extension
- Key files: DashboardView.tsx, ClientsView.tsx, Sidebar.tsx, Header.tsx, NoteModal.tsx

**`dist/`:**
- Purpose: Vite production build output
- Generated: Yes (created by `npm run build`)
- Committed: No (should be in .gitignore)

**`.planning/codebase/`:**
- Purpose: Architecture and code analysis documents
- Contains: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md, CONCERNS.md
- Generated: Yes (by GSD mapping tools)
- Committed: Yes

**`.impeccable/`:**

**`assets/`:**

## Naming Conventions

**Files:**
- React components: PascalCase.tsx (e.g., DashboardView.tsx, Header.tsx, NoteModal.tsx)
- Utilities/Data: camelCase.ts (e.g., data.ts, types.ts)
- Config files: lowercase or kebab-case with extensions (vite.config.ts, tsconfig.json)
- CSS: index.css (global styles)

**Directories:**
- Components folder: lowercase `components/`
- Source root: lowercase `src/`
- All lowercase unless proper noun abbreviation (e.g., `.impeccable/`)

**Functions/Variables:**
- React component functions: PascalCase (same as filename)
- State variables: camelCase (currentTab, setTab, selectedClient, etc.)
- Event handlers: camelCase with `handle` prefix (handleSelectClient, handleClearRisk, handleUpdateClientAttendance)
- Constants: UPPER_SNAKE_CASE (INITIAL_CLIENTS, INITIAL_STAFF)

**Types/Interfaces:**
- Domain types: PascalCase (Client, Staff, ClinicalNote, OperationalRisk, IndSession, AttendanceEntry)
- Type enums: Use union types with single quotes ('Present' | 'Absent' | 'Unconfirmed')

## Where to Add New Code

**New Feature (Domain-Specific Page):**
- Create View component: `src/components/[FeatureName]View.tsx`
  - Receive props from App: domain data, callbacks
  - Use local useState for UI state only
  - Export as default function
- Add tab ID to sidebar navItems array in `src/components/Sidebar.tsx`
- Add conditional render in `src/App.tsx` main viewport
- Add state & handler to `src/App.tsx` if new domain data needed

**New Component (Sub-component within existing View):**
- Create file: `src/components/[ComponentName].tsx`
- Keep in same `src/components/` directory
- Use PascalCase naming
- Import only from types.ts and other components

**New Data Type:**
- Add interface to `src/types.ts` following existing pattern (Client, Staff, etc.)
- Add export so importable by App and components

**New Initial Data/Fixture:**
- Add constant to `src/data.ts` following INITIAL_* naming pattern
- Export from data.ts for import in App.tsx

**Shared Utilities:**
- Currently no separate utils folder
- Recommendation: Create `src/utils/` if adding helper functions
- Place purely functional utilities there

## Import Path Conventions

**Path Alias:**
- Configured in tsconfig.json: `"@/*": ["./*"]`
- Usage: `import { Component } from '@/src/components/ComponentName'` (rarely used - most imports are relative)

**Current Pattern:** Most imports use relative paths
- Example: `import { Client } from '../types'` in components
- Example: `import Sidebar from './components/Sidebar'` in App.tsx

**Standard Order in Files:**
1. License/SPDX header (Apache-2.0)
2. React/external library imports
3. Local component imports
4. Type imports (sometimes grouped together)
5. Interface definitions
6. Component implementation
7. Export statement

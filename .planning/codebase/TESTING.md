## Recommended Testing Strategy

### Phase 1: Unit Tests (Foundation)
- Test pure functions from `src/data.ts`
- Test handler logic in isolation with mock props
- Target: 40% coverage (critical paths only)

### Phase 2: Component Tests
- Test individual component rendering with various props
- Test event handler invocations
- Target: 60% coverage

### Phase 3: Integration Tests
- Test parent-child prop drilling and callbacks
- Test complex state flows (e.g., select client → open modal → save note → update state)
- Target: 80% coverage

### Phase 4: E2E Tests
- Test full user workflows (if hosting externally)
- Test browser compatibility

## Recommended Testing Stack

**If Adding Tests:**

```json
{
  "devDependencies": {
    "vitest": "^1.0.0",
    "@testing-library/react": "^14.0.0",
    "@testing-library/user-event": "^14.0.0",
    "@vitest/ui": "^1.0.0",
    "jsdom": "^23.0.0"
  },
  "scripts": {
    "test": "vitest",
    "test:ui": "vitest --ui",
    "test:coverage": "vitest --coverage"
  }
}
```

**Rationale:**
- Vitest: Fast, Vite-native, ESM-first (matches project setup)
- React Testing Library: Focuses on user behavior, not implementation details
- JSDOM: Browser environment for component testing
